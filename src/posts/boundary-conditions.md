2024 年我集中刷了一段时间算法题。有道「字符串解码」（LeetCode 394）让我印象特别深  因为思路我三分钟就想出来了，然后**连挂四次**。

题目大意：给定 `3[a2[c]]` 这样的字符串，输出 `accaccacc`。嵌套的括号要正确展开。

思路确实清楚：**遇到数字入栈记倍数，遇到 `[` 入栈存状态，遇到 `]` 出栈拼接。** 标准做法。

我第一版写出来是这样：

```python
def decodeString(s: str) -> str:
    stack, num, cur = [], 0, ""
    for ch in s:
        if ch.isdigit():
            num = num * 10 + int(ch)
        elif ch == '[':
            stack.append((cur, num))
            cur, num = "", 0
        elif ch == ']':
            prev, k = stack.pop()
            cur = prev + cur * k
        else:
            cur += ch
    return cur
```

看起来没问题。跑示例 `3[a]2[bc]` 也对。提交  **挂。**

## 第一次挂：两位数的倍数

测试用例里有个 `12[a]`，我输出的是 `a`。

问题在 `num = num * 10 + int(ch)`  我脑子里想的是「累加数字」，但漏了一个前提：**`num` 必须在合适的时机清零。**

`3[a]` 的时候 `num` 是 3，遇到 `[` 清成 0，没问题。`12[a]` 也一样。那我为什么挂？

因为我把 `num` 的清零**和入栈写在了一起**：

```python
stack.append((cur, num))
cur, num = "", 0      #  这里
```

而真正的问题是我最初写的是 `num = 0` 写在了 `if ch.isdigit()` 分支里。改成上面这样之后两位数是好了，但我又发现了新问题。

## 第二次挂：`]` 之后还跟着字符

`3[a]bc` 这种。出栈后 `cur` 变成 `aaa`，然后接着把 `b`、`c` 拼上  这个我的代码是对的。

真正挂的是 `2[3[a]]` 这种**嵌套**：我自己试的时候没问题，提交挂了。

加了几行调试输出才看清  问题出在多层嵌套时的**拼回顺序**。内层 `3[a]` 出栈得到 `aaa`，回到外层时要拼成 `aaa * 2`。我第一次写的是：

```python
elif ch == ']':
    prev, k = stack.pop()
    cur = prev + cur * k      # 看起来对？
```

`prev + cur * k` 和 `prev + (cur * k)` 是同一个意思，运算符优先级没问题。**真正错的是我另一处**：我把 `num` 的清零从 `[` 分支挪到了 `isdigit` 分支里：

```python
if ch.isdigit():
    num = num * 10 + int(ch)
    num = 0                   #  挪错了地方，等于每次只记最后一位
```

结果 `12[a]` 变成 `2[a]`。这就是第一次挂的真凶  我当时改错了地方，反而把本来对的代码改坏了。

## 第三次和第四次：`return` 写错了变量

`return cur` 看着没问题。但我在调试过程中为了便于观察，临时加了个变量：

```python
result = cur
return result
```

改回来的时候手一抖，留了个 `return s`（原始字符串）。因为改了太多遍，眼睛已经看不出来了。

两次「挂在同样的地方」，第一次是 `return s`，第二次是 `return stack[0]`（我想当然地以为栈里存着结果）。

## 复盘：四个坑不在同一个层面

| 次数 | 现象 | 真实原因 |
|---|---|---|
| 1 | `12[a]` 输出 `a` | 变量清零位置写错（当时的判断） |
| 2 | `12[a]` 输出 `a` | 改 bug 时把对的代码改坏了 |
| 3 | 全部用例输出原字符串 | `return s`（调试残留） |
| 4 | 全部用例输出空 | `return stack[0]`（想当然） |

这四次里**没有一次是算法问题**。全是实现细节  而且第 2 次还属于「改 bug 改出新 bug」。

## 后来我改了做法

这道题之后，我刷题的方式变了：

**一、写完先过一遍边界清单，再提交。** 现在我的固定清单是：

- 空输入 / 单字符
- 数字一位 vs 多位（`9[a]` vs `10[a]`）
- 嵌套（`2[3[a]]`）
- 同级多个（`2[a]3[b]`）
- 数字后面不接 `[` 的非法情况（虽然题目保证合法，但值得想一下）

**二、调试用的代码必须有标记。** 我现在的习惯是调试输出统一加前缀：

```python
print(f"[DBG] cur={cur} stack={stack}")
```

提交前搜一遍 `[DBG]`，比凭记忆检查靠谱。**同类做法**：临时改 `return` 的时候，我会在行尾加 `# TEMP`  改成 `return s  # TEMP`，改回来的时候自然要处理这行。

**三、跑一遍全部样例，不只看自己构造的。** 我前两次挂都是因为只跑了题目给的示例（`3[a]2[bc]`），它恰好避开了两位数。**题目给的示例通常是最典型的，不是最全面的。**

**四、出问题时先怀疑「我刚才改了什么」，而不是「我的思路错了吗」。** 第 2 次挂的时候，我第一反应是重新推演算法，花了十几分钟。实际上我只是在改 bug 时把一行本来正确的代码挪错了位置  **看一眼 diff 就能发现。**

## 一个副产品：变量名

`cur` 这种变量名在短函数里没问题，但这个函数有 8 行、4 个状态变量（`stack`、`num`、`cur`、`prev`）。第 4 次挂就是因为我以为 `stack[0]` 存的是最终结果。

后来我会把这种「容易被想当然」的变量改名字：

- `cur` → `current_segment`（当前正在拼的片段）
- `prev` → `outer_prefix`（出栈后要拼回外层的前缀）

**名字写长一点，省下的调试时间比打字多。**

## 最后一句

刷题刷到后来我意识到，**「会做」和「能通过」之间隔着一层工程习惯。**

算法思路决定你能不能开始写，工程习惯决定你交上去的是不是对的。两个都得练  但后一个在刷题网站上不太会被强调，因为它不像算法那么「有难度」。
