做桌面宠物的第一个功能性 bug 不是动画不流畅，而是**点不动桌面图标**。

宠物是一个无边框、背景透明的窗口。窗口多大，它就吃掉多大的鼠标事件 —— 所以你想点宠物*旁边*的桌面图标，点在「空气」上，事件却被这个窗口收走了。视觉上是透明的，交互上是一堵墙。

## 先说那条走错的路

最直觉的做法：在 Python 里把宠物的形状再描述一遍，然后告诉系统「只有这块区域属于我」。

比如算一个矩形、或者一个圆：

```python
# 走错的那条路
rect = QRect(px, py, w, h)
window.setMask(QRegion(rect))
```

问题不在实现，而在**同一件事被描述了两遍**：一遍在 QML 的渲染里，一遍在 Python 的几何计算里。这两份描述迟早会分叉 

- 宠物在呼吸（缩放），尺寸每帧都在变；
- 贴到屏幕边缘时会侧躺，包围盒方向变了；
- 眨眼、换心情、挂一个未读徽章，都会改变真正的可见像素；
- 4 套形象的身体轮廓本来就不是同一个形状。

一旦分叉，症状就是「点击位置跑偏」：看得见的地方点不到，看不见的地方点得到。而且它**只在特定动画帧出现**，最难查。

## 现在的做法：渲染结果就是唯一真相

`pawpet/hitbox.py` 开头的注释把这件事写清楚了：

> The pet is drawn from several QML items and Canvas nodes. Repeating that geometry in Python would make the mouse target drift whenever an animation, edge pose, mood, or badge changes. The rendered image is the single source of truth, so the window mask is rebuilt from the pixels that are actually visible.

流程只有四步：

1. **抓一帧真实渲染结果**（`grabWindow`，拿到 `QImage`）。
2. **取 alpha 通道**，按阈值判断「这个像素算不算宠物身体」。
3. **逐行把连续的非透明像素合并成矩形**（span），组成一个 `QRegion`。
4. **`setMask(region)`** —— 交给系统，让它从窗口的输入区域里把透明部分真正摘掉。

关键在于第 4 步：这不是「在 Qt 里做个判断再把事件转发出去」，而是**系统层面就不再把那块区域当作这个窗口**。所以桌面图标能正常响应右键、拖拽、双击，性能也比自己转发事件好得多。

## 三个让它在真实使用中不崩的细节

### 一、阈值取 1，不取 0，也不取 128

```python
alpha_threshold: int = 1
```

- 取 `0`：抗锯齿边缘的半透明像素会有几像素的缝隙，细线部件（尾巴、耳朵尖）会漏出「点不到」的空洞。
- 取 `128`：边缘一圈不算命中，看起来像宠物「手感偏小」，贴边的时候尤其明显。
- 取 `1`：只要不是全透明就算身体。用户看到一点点像素，就会认为那里能点 —— 命中区和视觉一致。

### 二、按行合并 span，而不是一个像素一个矩形

一帧 300400 的宠物，如果每个不透明像素都变成一个 `QRect`，那就是几万个矩形。`QRegion` 扛不住，`setMask` 会明显卡顿。

按行合并成「连续段」之后，矩形数量掉到几百个量级 —— 这是能顺畅跑的规模。对应到代码里就是 `_alpha_spans()` 和 `_to_rect()` 这两个函数。

### 三、重建是有成本的，所以节流 + 只在需要时刷新

```python
interval_ms: int = 200
min_apply_interval_ms: int = 200
```

遮罩要跟着动画变，但**不需要每帧都重建**。200ms 一次已经足够人的点击不会精确落在「这一帧刚长出来的 3 个像素」上。

配套还有两个状态开关，都是踩过坑才加的：

- `suspend()` / `resume()`：覆盖层（指令栏、确认卡片）打开时先把遮罩挂起，否则遮罩和交互会互相抢，出现「卡片上的按钮点不动」。
- `interaction_in_progress()`：正在拖拽宠物的过程中，不要中途换遮罩 —— 换的那一瞬间可能把拖拽判定断掉。

还有一条兜底：抓帧失败时**恢复上一次的 region**，而不是清空遮罩。清空的后果是整块窗口重新变成一堵墙，比形状旧一点糟糕得多。

## 三条可以带走的经验

1. **凡是要跟渲染结果保持一致的东西，就不要在另一处重新描述它。** 几何、命中区、轮廓、边框高亮都属于这一类。让「实际画出来的像素」当唯一真相，比让两份代码保持同步可靠得多。
2. **阈值是拿来换稳定性的。** 判断「算不算」这类问题，边界上永远有一圈模糊地带，选一个让用户感知和实现一致的阈值，比追求理论精确有用。
3. **重建的代价要设计进去。** 节流、挂起、恢复、失败兜底 —— 这四个词在「每帧都要做的事」里缺一个都会出问题。

现在宠物的呼吸、眨眼、贴边侧躺、换形象，点击位置都不会跑偏。用户感知到的只是：**宠物就是宠物，旁边的桌面还是桌面。**
